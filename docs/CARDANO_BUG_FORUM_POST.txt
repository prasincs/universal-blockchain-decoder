Subject: [BUG] Invalid Cardano Transaction CBOR Examples - Cannot Decode with Pallas

---

Hi Cardano community,

I'm implementing a Cardano transaction decoder and discovered that commonly-cited transaction CBOR examples **fail to decode with the official pallas library**. These examples violate the CDDL specification and should be removed from documentation.

## The Problem

Two transaction examples I found in various docs cannot be decoded:

**Example 1** (6-element array):
```
86a500818258201db731b2349b2a16745512809c86756ed42e2547f8cf7b93d8803bd88bd68338...
```
- Has 6 CBOR elements (spec requires 3-4)
- Pallas error: "unexpected type indefinite array at position 182"

**Example 2** (indefinite arrays):
```
839f8200d8185826825820e981442c2be40475bb42193ca35907861d90715854de6fcba...
```
- Uses indefinite-length arrays (violates CBOR RFC 8949)
- Pallas error: "unexpected type indefinite array at position 1"

## Verification

I tested with pallas (official Rust library):

```rust
use pallas_primitives::alonzo::MintedTx;
let tx_bytes = hex::decode(tx_hex)?;
let result = minicbor::decode::<MintedTx>(&tx_bytes);
// Result: ❌ FAIL (both examples)
```

## Impact

- Developers waste time debugging invalid examples
- Creates incompatible parser implementations
- Erodes trust in documentation

## Solution

Replace with validated examples from:

1. **Pallas test fixtures**: https://github.com/txpipe/pallas/tree/main/pallas-applying/tests
2. **Cardano-ledger test suite**: https://github.com/IntersectMBO/cardano-ledger
3. **Export from cardano-cli**: `cardano-cli transaction view --tx-file tx.signed`

## Correct Format

Per CDDL spec:
```
transaction = [tx_body, witness_set, bool, auxiliary_data/null]
```
Must use definite-length encoding (4 or 3 elements).

2. Who maintains affected documentation?
3. Can we create an official "validated examples" repository?
